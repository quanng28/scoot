# Technology Decisions: Seated Exercise Review

> **Historical design document.** Preserved for engineering context; planned features and earlier decisions may differ from the current app. See the [current README](../README.md) and [architecture](../docs/scoot-architecture.md) for implemented behavior.

Updated: October 25, 2026. These are implementation decisions and verification gates; current code evidence is recorded in the companion task checklist. Optional public video sharing is a confirmed MVP requirement with implementation/testing pending. Vercel hosting remains planned, not deployed; a video storage provider has not been selected.

## 1. Decisions in plain language

- **Track joints:** MediaPipe Tasks Vision Pose Landmarker, running in a browser worker.
- **Recognize the activity:** required experimental Jev integration using derived movement features, compared with an explainable local rules baseline. Manual selection always works without Jev.
- **Measure movement:** exercise-specific TypeScript geometry, quality gates, and state machines. Neither Jev nor a chat LLM computes clinical scores.
- **Store evidence:** video and session records stay local in IndexedDB by default. Full measurement streams, notes, labels and reports are not part of video publication.
- **Share video:** after Stop/results, an explicit Share video action publishes only the selected finalized compressed recording and returns a stable public HTTPS URL opening the video directly on another device without an account. Show that anyone with the link can view or forward it; no upload occurs just from Stop.
- **Protect the Jev key:** a small server-side Vercel Function proxies opt-in derived-feature requests. Video never enters Jev or its classification endpoint; optional public video storage is a separate path. No browser secret or Supabase database is selected.
- **Build the interface:** React + TypeScript + Vite, simple CSS, React reducer/context state, runtime schema validation.
- **Verify:** Vitest + React Testing Library; Playwright for browser flows; physical iPhone Safari for camera, memory, recording, storage, replay and export. Public sharing additionally needs actual uploaded-video playback and seeking on a second device without login.

Required Jev integration means the demo must demonstrate a genuine, consented request/response and failure handling. It does not mean every user must consent or every session must have a network connection. Missing credentials are a delivery blocker for that capability, not permission to substitute a fake response.

## 3. Data path and opt-in boundary

1. Camera frames → on-device MediaPipe worker → timestamped landmarks.
2. Local quality/feature extraction → local rules and exercise-specific measurements. No provider call is allowed to turn invalid tracking into valid data.
3. If the supervisor/participant explicitly opts in for the current session: send only allowlisted derived movement features through `POST /api/classify-exercise` → Jev → validated suggestion.
4. Show uncertainty and require confirmation before changing an active exercise. A change ends the current task and repeats relevant setup. Never change rehabilitation/wellness mode from a prediction.
5. Store video, detailed observations, notes, local identity labels and report locally. Store the model ID, suggestion and request status locally for inspection.
6. Only after recording finalization and an explicit Share video action: selected compressed recording → separate public video storage → stable public HTTPS video URL. Send no measurements, criteria/flags, notes, participant/session identifiers, raw landmarks or report alongside it. This is independent of Jev consent and never routes video through the classifier.

The outbound **Jev feature** schema may include relative sample times, projected joint-angle trajectories, normalized displacement/velocity features, relevant quality summaries and a feature-schema version. It must exclude video/images/audio, raw image/landmark coordinates, names, participant/session identifiers, therapist notes, medical history and free-form prompts. Derived movement features are still potentially sensitive; do not label them anonymous merely because names are absent. Define a minimal feature subset that both classifiers can consume and test its information loss.

Consent must state who receives the features, purpose, timing and retention limitations; default off, available to inspect, revocable during the session. Revocation stops future requests, cancels queued/in-flight work where possible and discards late results; it cannot retract requests already received by the provider. Manual/local capture remains usable without consent. Application code must not log feature payloads; account/provider retention terms must be disclosed accurately, not invented as zero retention. See [TypeSafe data handling](https://help.typesafe.ai/articles/5974925716-how-is-submitted-data-used-or-retained).

No automatic cloud upload of session records, reports or video. Selecting an exercise, granting camera permission, enabling demo mode, pressing Stop, saving results or opting into Jev must not publish video. Share video is the separate explicit publication action, with the visible notice “Anyone with this link can view or forward this video.” The recording itself can identify people or surroundings even when metadata is minimized; do not call it anonymous. Local deletion does not delete the uploaded public copy or recall forwarded links. No recipient account, private/expiring-link flow, automatic retention/deletion feature or control over recipient copies is promised. Confirm applicable data handling and suitability before participant-data use; team/synthetic fixtures establish wiring only.

## 4. Minimum server controls and failure behavior

- `JEV_API_KEY` is server-only; never `VITE_*`, committed, exposed to the browser or returned in errors. Do not ask the user to paste a key into chat. Configure it through the hosting secret mechanism.
- Validate POST method, allowed origin as an additional restriction, feature schema/version, finite numeric values, payload size, permitted categories and bounded request cadence. Origin checks alone are not authentication.
- Protect the paid endpoint with a demo access gate (e.g. server-verified demo code exchanged for an expiring signed session capability) and shared/platform rate limits. This is abuse control, not verified clinician identity. Do not treat a JavaScript-visible shared secret or an in-memory serverless counter as adequate protection. Prefer platform WAF rate limiting if available; verify its plan/limit behavior before selecting a fallback shared limiter. [Vercel WAF](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting)
- Establish explicit per-session and global request/spend caps before live testing. Reaching a limit stops Jev calls and keeps manual/local operation; do not retry indefinitely. Do not create paid services or purchases without the user's authorization.
- One active classification request at a time; drop superseded queued windows. Configure a bounded window duration, minimum quality, cadence, payload size, timeout and retry policy in versioned engineering settings after the device/API spike. These are not clinical thresholds.
- Reject unrecognized labels, missing/invalid probabilities, schema mismatch, stale session/task IDs and late responses. Store only valid, current suggestions. A well-formed high-confidence answer can still be wrong.
- Handle missing credentials, timeout, network loss, HTTP/auth/rate-limit errors, user cancellation and provider outage with an explicit “Recognition unavailable—select exercise manually” state. None must stop or corrupt an ongoing local recording.
- Test provider failures with deterministic mocks; verify the real API separately with explicit consent and approved test payloads. Do not claim mocked integration proves live Jev works.

### Public video upload and playback gates

These requirements apply to the separate sharing path, not the Jev endpoint. Implementation and all upload/playback evidence remain pending.

- Publish only the selected finalized, usable compressed recording after Share video. Reuse a supported browser-encoded video where practical; do not substitute a GIF or require an encoded metrics/notes overlay. No participant/session identifiers in upload metadata, filenames or the returned URL.
- Select the storage provider and declare supported video MIME/codec, maximum duration/file size, upload timeout and bounded retry policy before implementation. Validate those bounds at the upload boundary; do not infer that planned Vercel app hosting provides unlimited video storage or transfer. Provider resources, costs and actual uploads require their own authorized implementation step.
- Return an ordinary stable public HTTPS URL that directly serves the uploaded video, with the correct media type and working remote seeking. The URL must work independently of the originating browser session and open on another device without login, app account, report page, doctor portal or an expiring access-token flow.
- Show uploading, successful publication and failed/cancelled states. Only confirmed success exposes a playable URL. Failed/cancelled sharing preserves local recording/results; another upload requires a new explicit action rather than an automatic retry loop. Reject unusable/unfinished recordings without claiming publication succeeded.
- Copying or opening the returned URL preserves the original video, results and inline local player, including on iPhone Safari. Copy must not navigate; an open-link control uses a new tab. Keep the URL available for repeated copying and persist it with the local session record when Save is used, subject to normal IndexedDB limits. The public HTTPS URL must remain playable after closing/reloading the originating app; never expose an ephemeral `blob:` URL as the shared link. This does not synchronize complete sessions across devices.
- Verify that Stop alone sends no upload, only the selected video is sent, no session/measurement/identifier payload accompanies it, and the actual remote format plays/seeks on a second device. Verify repeated copy/open leaves the original inline video playable, remote playback survives original-app closure/reload, and Save/reopen retains the video and share URL for copying again. Also verify missing/invalid media, size limits, interrupted/network-failed upload and local deletion messaging. A local Blob URL, fake upload response or same-device decode does not satisfy remote-sharing acceptance.

## 5. Model evaluation and release decision

Separate **wiring**, **experimental demonstration**, and **participant-facing recognition readiness**.

- Wiring: deterministic fixtures verify schema, request routing, consent, no-network behavior, rejection, response validation and manual confirmation. These do not establish classification accuracy.
- Experimental demo: a real pinned-model request/response on approved team/synthetic-derived movement features passes through the protected server and produces an inspectable suggestion; costs and latency are recorded. It remains labeled experimental.
- Participant-facing readiness: define ethically sourced representative recordings and participant-disjoint train/tune/test splits, including affected-side variation, support, limited range, camera conditions and confusing upper-limb exercises. Do not send the expected/selected label to either classifier. Compare local rules and Jev using identical allowed feature inputs.
- Report per-class precision/recall, confusion matrix, confidence calibration, confident wrong labels, accepted coverage, unknown/other/rest/transition handling, poor-tracking rejection, end-to-end p50/p95 latency and requests/cost per session. Coverage must accompany accuracy so a model cannot appear better solely by rejecting most examples. Report untested exercises/conditions.
- Set numerical acceptance targets before evaluating the held-out test set, with the supervising clinical collaborator. No targets or clinical accuracy results are established by this document. Do not tune on test participants or promote on vendor benchmarks.

If Jev does not improve the agreed recognition trade-off, the required experimental integration is still reported honestly; do not remove its evaluation evidence or claim it is the best. Manual selection remains the product fallback. A trained temporal classifier is a later candidate requiring its own dataset/model/runtime decision.

# Tasks: SCOOT — seated camera, Gemini voice and report

> **Historical design document.** Preserved for engineering context; planned features and earlier decisions may differ from the current app. See the [current README](../README.md) and [architecture](../docs/scoot-architecture.md) for implemented behavior.

Updated October 25, 2026. Active plan for the [revised PRD](prd-post-stroke-seated-reach-review.md) and the user's five-view iPhone Safari wireframes. This is a documentation revision, not evidence that new features have been implemented. The previous checklist remains in the historical archive (historical reference; retained in the private development archive).

**Target flow:** choose a seated exercise → confirm/open camera → live skeleton before recording → brief guided setup → explicit Record → up to 60 seconds with final-five-second countdown and short spoken cues → Stop → video on top, report/charts below → local Save and optional public Share video/Copy link. The standing stick figures in the screenshots are placeholders, not supported activities. Do not recreate Safari's own browser toolbar.

- Check main/remotes and unrelated changes first. Start implementation from the reviewed current main on a `codex/` branch; do not merge the conflicting old adapter branch wholesale. Preserve the user's unrelated `.gitignore` and other local edits.
- Work in dependency order below. Each checkbox requires its described implementation and evidence; planning, a mock, an API key or a deployment URL alone is not completion. Record exact commands, commit, actual results and limitations when checking it.

Review shared contracts together. Retain tested producer/consumer behavior rather than build another parallel app or storage schema.
- Keep required local operations functional without a key, consent or network. Stop and tracking rejection never depend on model output. All movements stay seated; SR01 is the reviewed pilot; concurrent `d8da0e3` adds an SR02 app flow needing its own acceptance. Catalog entries are not enabled analyzers.
- Current standard Gemini API terms restrict clinical practice/medical advice and sensitive personal input on unpaid services. Start report evaluation with fictional symptoms/clinician context and synthetic movement fixtures; do not send real clinical data merely because a key exists. Verify the actual service/agreement before changing this gate. See PRD FR-21.
- This plan removes Jev as a product dependency. Concurrent main commit `e4df442` removes its runtime; A below now verifies completeness and reusable boundaries rather than redoing deleted modules. Existing historical provider tests are not Gemini acceptance, and the old approval for a provider smoke request must not be reused for Gemini.
